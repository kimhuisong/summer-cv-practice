## 1. 動機と問い

**問い: スキップ接続は何を担っているのか？**

セグメンテーションは「各画素が何か（what）」と「どこにあるか（where）」を同時に答える問題である。
エンコーダでプーリングを重ねると、受容野が広がって「何が写っているか」という意味的な情報は得やすくなるが、解像度が落ちて「どこか」という位置の情報は粗くなる。
U-Net はエンコーダの高解像度な特徴をデコーダへ直接渡す（スキップ接続）。この接続が実際に担っているのは何か、を**接続だけを外した対照実験**で確かめる。

**仮説**: スキップ接続を外すと、全体の精度（mIoU）よりも**境界クラスの精度が大きく落ちる**。
理由: 前景/背景の判定は大域的な意味（ボトルネックの低解像度特徴）でもおおむね可能だが、境界は数画素幅の細い領域で、プーリングで失われる細かい位置情報が必要だから。

この「データの構造（画像の空間的局所性）に合わせたモデル設計」は、リポジトリ全体の軸（README 参照）の 02 にあたる。

## 2. データセットの選定根拠

- **Oxford-IIIT Pet**（`torchvision.datasets.OxfordIIITPet`, `target_types="segmentation"`）。37品種のペット画像に、画素単位の trimap（前景・背景・境界）が付く。公式の trainval 3,680枚 / test 3,669枚。
- 「境界」クラスがあるため、**細かい位置情報をどれだけ復元できているかを直接評価**でき、スキップ接続の効果検証に適している。
- 登録不要で、128×128 にリサイズすれば T4 で一晩（実際には1条件数十分以内）で回せる規模。
- 前処理: 画像は bilinear、マスクは nearest で 128×128 にリサイズ。ラベルは 0=前景、1=背景、2=境界（torchvision の 1/2/3 を振り替え）。
- 分割: 公式 trainval を seed 固定で 9:1 に分けて train / val（val は best epoch の選択にのみ使用）、公式 test を最終評価に使う。
- 注意点: 境界クラスは画素数が少ない（クラス不均衡）。本実験では A・B とも通常のクロスエントロピーで学習し、境界を優遇する重み付けはしない（A/B の差を損失設計に混ぜないため）。

## 3. 前提となる基礎概念

### 3.1 畳み込みの計算

入力 $x$（$C_{in}$ チャネル）に、カーネル $w$（サイズ $k\times k$）を滑らせて出力を作る:

$$
y_{c_o}(i,j)=b_{c_o}+\sum_{c=1}^{C_{in}}\sum_{u=0}^{k-1}\sum_{v=0}^{k-1} w_{c_o,c}(u,v)\,x_c(i+u-p,\;j+v-p)
$$

- 同じ重み $w$ を全位置で使い回す（**重み共有**）→ 並進等変性とパラメータ削減。1 画素の出力は近傍 $k\times k$ だけに依存する（**局所性**）。
- 出力サイズ: $H_{out}=\left\lfloor \dfrac{H+2p-k}{s}+1\right\rfloor$（$p$: パディング、$s$: ストライド）。本実装は $k=3,\,p=1,\,s=1$ で空間サイズを保つ。
- パラメータ数: $C_{out}\,(C_{in}k^2+1)$（BatchNorm 前の畳み込みは bias なしにしている）。
- 形状の例: `(B, 3, 128, 128) -> Conv3x3(3→32) -> (B, 32, 128, 128)`

### 3.2 プーリング

$2\times2$ max pooling は、各 $2\times2$ 領域の最大値だけを残す:

$$
y(i,j)=\max_{0\le u,v<2} x(2i+u,\;2j+v)
$$

解像度が縦横 $1/2$ になり、計算量が減り、少しの位置ずれに頑健になり、後続の受容野が広がる。一方で**「最大値がどの位置にあったか」という情報は捨てられる**。これが U-Net でスキップ接続が必要になる理由の出発点である。

### 3.3 受容野

ある出力画素が依存する入力画素の範囲。層ごとに受容野 $r$ とジャンプ（入力画素何個分で出力が1つ動くか）$j$ を次式で更新する:

$$
r_{l}=r_{l-1}+(k_l-1)\,j_{l-1},\qquad j_l=j_{l-1}\,s_l
$$

本実装のエンコーダ（$3\times3$ 畳み込み2回 + $2\times2$ プーリングを繰り返す）で計算すると:

| 位置 | 受容野 | ジャンプ |
|---|---|---|
| enc0（畳み込み×2） | 5 | 1 |
| pool → enc1 | 14 | 2 |
| pool → enc2 | 32 | 4 |
| pool → enc3 | 68 | 8 |
| pool → bottleneck | 140 | 16 |

ボトルネックの受容野（140）は入力（128）より大きく、画像全体を見て「これは犬の体だ」と判断できる。一方、高解像度側（enc0 の 5 画素など）は狭い範囲しか見ないが、細かい位置を正確に保持している。
→ **深い層は「何か」（広い受容野・低解像度）、浅い層は「どこか」（狭い受容野・高解像度）**。スキップ接続はこの両者をデコーダで出会わせる。

### 3.4 転置畳み込み（アップサンプリング）

デコーダで解像度を戻す学習可能な演算。畳み込みの出力サイズの式を逆にたどる形で、$k=2,\,s=2$ のとき:

$$
H_{out}=(H_{in}-1)\,s-2p+k=2H_{in}
$$

入力の各画素に $2\times2$ のカーネルを掛けて、重ならないように出力へ敷き詰める。形状の例: `(B, 512, 8, 8) -> ConvTranspose2d(512→256, k=2, s=2) -> (B, 256, 16, 16)`。
補間（最近傍・bilinear）と違い、拡大のしかた自体を学習できる。ただし**失われた細部を無から作るわけではない**（元の低解像度特徴にない情報は復元できない）。ここが B の弱点になると予想している。

### 3.5 エンコーダ・デコーダ構造

- **エンコーダ**: 畳み込みとプーリングで、解像度を下げつつチャネルを増やし、抽象的な特徴を作る。本実装は `128→64→32→16→8`、チャネルは `32→64→128→256→512`。
- **デコーダ**: 転置畳み込みで解像度を戻し、最後に $1\times1$ 畳み込みで画素ごとのクラスロジット `(B, 3, 128, 128)` を出す。
- **ボトルネック**: 8×8 の最も圧縮された表現。B（スキップなし）では、デコーダはこの 8×8×512 の情報**だけ**から全解像度のマスクを描く（情報のボトルネック）。
- **スキップ接続（A）**: デコーダの各段で、同じ解像度のエンコーダ特徴を channel 方向に連結する: `(B, C, h, w) ⊕ (B, C, h, w) -> (B, 2C, h, w)`。

### 3.6 IoU（Intersection over Union）

クラス $c$ の IoU は、予測領域と正解領域の重なりの割合:

$$
\mathrm{IoU}_c=\frac{|P_c\cap G_c|}{|P_c\cup G_c|}=\frac{TP_c}{TP_c+FP_c+FN_c},\qquad
\mathrm{mIoU}=\frac{1}{C}\sum_{c=1}^{C}\mathrm{IoU}_c
$$

本実装は test 全体の混同行列（行=正解、列=予測）を累積してから、$TP_c=\mathrm{cm}_{cc}$、$FN_c=\sum_j \mathrm{cm}_{cj}-TP_c$、$FP_c=\sum_i \mathrm{cm}_{ic}-TP_c$ で IoU を計算する（画像ごとの IoU の平均ではない）。
画素精度（accuracy）は面積の大きい背景・前景に支配されるが、IoU は細い境界クラスの誤りを敏感に反映する。数画素幅の境界は、1〜2画素のずれで IoU が大きく変わるため、「位置の精度」を測るのに向いている。

## 4. モデルの構造

`model.py` の `UNet(use_skip=...)`。base=32, depth=4。

| 段 | 解像度 | チャネル | 備考 |
|---|---|---|---|
| enc0 | 128 | 3 → 32 | DoubleConv（3×3 conv–BN–ReLU を2回） |
| enc1 | 64 | 32 → 64 | 直前に 2×2 max pool |
| enc2 | 32 | 64 → 128 | 〃 |
| enc3 | 16 | 128 → 256 | 〃 |
| bottleneck | 8 | 256 → 512 | 〃 |
| dec3 | 16 | 512 → 256 | 転置畳み込み → (A: enc3 と concat) → DoubleConv |
| dec2 | 32 | 256 → 128 | 同上（enc2） |
| dec1 | 64 | 128 → 64 | 同上（enc1） |
| dec0 | 128 | 64 → 32 | 同上（enc0） |
| head | 128 | 32 → 3 | 1×1 conv |

- **A（スキップあり）**: 各 dec で転置畳み込みの出力とエンコーダ特徴を concat（DoubleConv の入力は $2C$ チャネル）。
- **B（スキップなし）**: concat を取り除いただけ（DoubleConv の入力は $C$ チャネル）。それ以外は同一。
- **パラメータ数の差**（`python model.py` で算出）: A = 7,763,107、B = 6,979,747（A より 783,360 少ない、約10%）。B の方が少ない。差はすべて、デコーダ各段の DoubleConv の第1畳み込みの入力チャネルが $2C\to C$ になることによる。
  - この差が結果に影響する可能性は排除できない（B が劣るのは「スキップがない」からか「パラメータが少ない」からか）。考察で扱う。

## 付録A: 発表で聞かれそうな質問と答え

**Q1. なぜ境界クラスで差が出ると予想したのですか？**
A. 境界は数画素幅の細い領域で、位置の精度が必要だからです。プーリングを経たボトルネックの特徴は「何が写っているか」には強いが位置の細部を失っており、B ではデコーダがそれだけから輪郭を描き直す必要があります。A は高解像度のエンコーダ特徴を直接受け取れます。

**Q2. A と B でパラメータ数が違うのは不公平では？**
A. その通りで限界として明記しています。差は構造上必然的に生じる（デコーダの入力チャネルが半分になる）ためそのまま比較しています。パラメータ数を揃えた B を追加して切り分けるのが次のステップです。

**Q3. 転置畳み込みだけで細部は復元できないのですか？**
A. 転置畳み込みは拡大のしかたを学習できますが、入力に含まれない情報は作れません。8×8 に圧縮された時点で失われた細部は、スキップ接続なしには戻りません（情報の上限はボトルネックで決まる）。

**Q4. mIoU だけでなく境界の IoU を見る理由は？**
A. 前景・背景は面積が大きく、境界が多少ずれても平均に与える影響は小さいからです。境界 IoU は位置精度に直接敏感で、仮説の検証に適しています。

**Q5. 受容野が大きければ位置も分かるのでは？**
A. 受容野は「どの範囲を見ているか」であり、プーリング後は特徴マップ上の 1 画素が入力の 16×16 画素に対応します。広く見えても出力の位置分解能は粗いままです。

**Q6. スキップ接続は結局何を担っていると言えますか？**
A. 本実験の枠内では、「高解像度な空間情報をデコーダに直接渡す役割」の効果を境界の精度で見ます（結果はTODO）。ただし勾配が伝わりやすくなる効果もあり、本実験だけでは切り分けられません。

**Q7. 画像ごとに IoU を平均しないのはなぜですか？**
A. 画像によっては境界クラスの正解画素がごく少なく IoU が不安定になるためです。test 全体の混同行列から計算すると安定します。

## 付録B: 理解度チェック問題

**問1.** 入力 `(B, 3, 128, 128)` に `Conv2d(3, 32, k=3, p=1, s=1)` を適用した出力の形状と、パラメータ数（bias あり）は？

<details><summary>答え</summary>

形状は `(B, 32, 128, 128)`。パラメータ数は $32\times(3\times3\times3+1)=896$。
</details>

**問2.** `ConvTranspose2d(512, 256, k=2, s=2)` に `(B, 512, 8, 8)` を入力したときの出力形状は？

<details><summary>答え</summary>

$H_{out}=(8-1)\cdot 2-0+2=16$ なので `(B, 256, 16, 16)`。
</details>

**問3.** 3×3 畳み込み2回の直後に 2×2 プーリングを置き、その後にまた 3×3 畳み込みを1回かけたときの受容野は？

<details><summary>答え</summary>

畳み込み2回で $1+2+2=5$、プーリングで $5+(2-1)\cdot1=6$（ジャンプ2）、畳み込み1回で $6+2\cdot2=10$。
</details>

**問4.** 混同行列が `[[8,2,0],[1,15,4],[0,3,7]]`（行=正解、列=予測）のとき、クラス2のIoUは？

<details><summary>答え</summary>

$TP=7$、$FN=0+3=3$、$FP=0+4=4$。$\mathrm{IoU}=7/(7+4+3)=0.5$。
</details>

**問5.** B（スキップなし）の DoubleConv の入力チャネルが A の半分になるのはなぜか？

<details><summary>答え</summary>

A は転置畳み込みの出力 $C$ とエンコーダ特徴 $C$ を連結して $2C$ チャネルを入力するが、B は連結しないので転置畳み込みの出力 $C$ のみが入力になるため。
</details>

**問6.** 「全体の mIoU はあまり変わらないのに境界 IoU だけ大きく下がる」場合、どんな解釈ができるか？

<details><summary>答え</summary>

前景・背景の大まかな判定には大域的な意味情報で足りるが、境界の精密な位置には高解像度の空間情報が必要であり、スキップ接続がその供給を担っていることを示唆する。ただし、パラメータ数の差や最適化のしやすさの違いも別の要因として検討が必要。
</details>
