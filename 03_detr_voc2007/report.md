## 1. 動機と問い

01（PointNet）では「入力が順序のない集合」、02（U-Net）では「入力が空間的な局所構造を持つ画像」を扱った。
03 では向きを変えて、**出力が集合**になる問題を扱う。物体検出の答えは「画像の中の物体の集合」で、
個数は画像ごとに違い、並び順に意味がない。

従来の検出器（Faster R-CNN、YOLO など）は、アンカーやグリッドごとに大量の候補を出し、
最後に **NMS（Non-Maximum Suppression）** という手作りの後処理で重複を消して「集合」に整えていた。
DETR は、Transformer と **ハンガリアンマッチングによる集合予測の損失** によって、
最初から集合を直接出力するように学習する。出力の構造（集合）に合わせて、モデルと損失の構造を設計した例である。

この実装で確かめたい問いは2つ。

1. **事前学習はどれだけ効くのか。**
   COCO で検出まで学習済みの DETR 全体から始める場合（A）と、バックボーンだけ ImageNet 事前学習で
   Transformer はゼロから学習する場合（B）を、同じエポック数・同じ設定で比べる。
2. **DETR はなぜ NMS なしで動くのか。**
   理論的には「一対一マッチングの損失が重複予測を罰するから」と説明される。これを
   (a) ライブラリのコードを読んで仕組みを確認し、(b) 小さな例で数値的に確かめ、
   (c) 学習済みモデルに NMS を後から足して mAP が変わるか、重複検出がどれくらいあるかを測って確かめる。

**仮説:** B は同じエポック数（5エポック）ではほとんど学習できず、DETR の収束の遅さが確認できる。
A は数エポックで実用的な mAP に達する。

## 2. データセットの選定根拠

**Pascal VOC 2007**（trainval 5,011枚で学習、test 4,952枚で評価、20クラス）を使う。

- 20クラスの物体検出の標準ベンチマークで、mAP@0.5 による比較の文脈が豊富。
- COCO（学習画像 約11.8万枚、80クラス）より一桁小さく、T4 GPU 1枚・1条件40分という制約の中で
  ファインチューニングの実験が回せる。
- 1枚あたりの物体数が少なめ（平均2〜3個程度）で、DETR の100個のクエリに対して十分余裕がある。

**注意点（結果の解釈に直結する）:**
VOC の20クラスは、すべて COCO の80クラスに対応するクラスがある
（aeroplane↔airplane、motorbike↔motorcycle、sofa↔couch、tvmonitor↔tv、diningtable↔dining table、
pottedplant↔potted plant など。他は同名）。
つまり条件 A は「**見たことのあるクラスを、見たことのある種類の写真で検出する**」状態から始まる。

また COCO も VOC も Flickr の写真から集められているので、画像の傾向（撮影スタイル・構図）も近い。

## 3. 前提となる基礎概念

### 3.1 Attention（Q・K・V の計算）

Attention は「各要素が、他のどの要素の情報をどれだけ取り込むか」をデータから決める仕組み。
入力の各要素から3種類のベクトルを線形変換で作る。

- **Query（問い合わせ）** $q_i = W_Q x_i$ … 「自分はどんな情報が欲しいか」
- **Key（索引）** $k_j = W_K x_j$ … 「自分はどんな情報を持っているか」
- **Value（中身）** $v_j = W_V x_j$ … 「実際に渡す情報」

Query と Key の内積で「関連度」を測り、softmax で重みにして Value を重み付き平均する。

$$
\mathrm{Attention}(Q, K, V) = \mathrm{softmax}\!\left(\frac{Q K^\top}{\sqrt{d_k}}\right) V
$$

- $Q \in \mathbb{R}^{N_q \times d_k}$, $K \in \mathbb{R}^{N_k \times d_k}$, $V \in \mathbb{R}^{N_k \times d_v}$。
  $QK^\top$ は $(N_q, N_k)$ の行列で、$i$ 行目を softmax したものが「Query $i$ が各 Key にどれだけ注目するか」の確率分布になる。
- $\sqrt{d_k}$ で割るのは、次元が大きいと内積の分散が $d_k$ に比例して大きくなり、softmax が極端に尖って勾配が消えるのを防ぐため。
- **Multi-Head Attention**: $d_{model}=256$ を 8 個のヘッド（各32次元）に分け、それぞれ別の $W_Q, W_K, W_V$ で Attention を計算して連結する。
  ヘッドごとに違う種類の関係（位置の近さ、色、形など）に注目できる。

ライブラリの実装（`eager_attention_forward`）はまさにこの式で、
`attn_weights = softmax(query @ key^T * scaling + mask)`、`attn_output = attn_weights @ value` となっている。
`mask` にはパディング画素の位置に大きな負の値が入り、softmax 後の重みがほぼ 0 になる（パディングを見ない）。

**self-attention** は Q・K・V を同じ集合から作る（集合の要素どうしが互いを見る）。
**cross-attention** は Q をある集合から、K・V を別の集合から作る（ある集合が別の集合を見る）。

畳み込みとの違い: 畳み込みは「近くの画素だけを、位置ごとに固定の重みで」混ぜる（02 の局所性の帰納バイアス）。
Attention は「どの位置とも、入力の中身に応じた重みで」混ぜる。画像全体の関係（例: 2つの物体の位置関係、
同じ物体の離れた部分）を1層で扱える代わりに、局所性という強い帰納バイアスを持たないので、学習に多くのデータと時間を要する。

さらに Attention は入力の**並べ替えに対して等変**（入力の順番を入れ替えると出力も同じように入れ替わるだけ）。
これは 01 の PointNet と同じ「集合を扱う」性質であり、位置の情報が必要なら**位置埋め込み**を足して与える必要がある。

### 3.2 Transformer

Transformer は Attention を中心にした層を積み重ねたネットワーク。DETR の1層は次の構造（Post-LN）。

- **エンコーダ層:** $x \leftarrow \mathrm{LN}(x + \mathrm{SelfAttn}(x))$, $x \leftarrow \mathrm{LN}(x + \mathrm{FFN}(x))$
- **デコーダ層:** $y \leftarrow \mathrm{LN}(y + \mathrm{SelfAttn}(y))$,
  $y \leftarrow \mathrm{LN}(y + \mathrm{CrossAttn}(y, \text{エンコーダ出力}))$,
  $y \leftarrow \mathrm{LN}(y + \mathrm{FFN}(y))$

FFN は位置ごとの2層 MLP（256→2048→256）、LN は Layer Normalization、$x + \cdots$ は残差接続。

DETR での位置埋め込みの入れ方には特徴がある（ライブラリの `DetrSelfAttention` / `DetrCrossAttention` で確認）:
- エンコーダの self-attention: 画像の2次元の sin/cos 位置埋め込みを **Q と K にだけ** 足す（V には足さない）。
- デコーダの cross-attention: Q には物体クエリの埋め込み、K には画像の位置埋め込みを足す。V には何も足さない。
- 位置埋め込みを毎層で足し直すので、深い層でも「どこにあるか」の情報が薄れない。

### 3.3 物体クエリ

DETR のデコーダには、画像とは無関係な **学習可能なベクトル 100 個**（`query_position_embeddings`、各256次元）を入れる。
これが **物体クエリ** で、「物体を1個ずつ入れる100個の空き枠（スロット）」と考えるとよい。

- デコーダの入力そのものはゼロベクトルで、物体クエリは各層で Q（と self-attention の K）に**位置埋め込みのように足される**。
- **self-attention** でクエリどうしが情報を交換する。これにより「あのクエリが犬を取ったから、自分は別の物体を担当する」
  という**協調**ができる。重複予測を避けられる仕組みの一部である。
- **cross-attention** で各クエリが画像特徴（エンコーダ出力、$h \times w$ 個）を見て、自分の担当する物体の情報を集める。
  このときの Attention の重み $(Q{=}100, h \cdot w)$ を可視化したものが `cross_attention_*.png` で、
  「どのクエリが画像のどこを見ているか」が直接わかる。元論文では、物体の**端（頭・足・輪郭）**に注目する様子が報告されている。
- 学習が進むと、クエリごとに「画像のこのあたりの、この大きさの物体」を担当するように分業する（`query_specialization.png` で確認する）。

### 3.4 集合予測

DETR の出力は 100 個の（クラス確率, ボックス）の組 $\hat{y} = \{\hat{y}_i\}_{i=1}^{100}$。
クラスは 20 クラス + **「物体なし（∅, no-object）」** の 21 通り。画像中の物体が3個なら、
理想的には 3 個のクエリが物体を、残り 97 個が「物体なし」を出す。

問題は「どの予測をどの正解と比べて損失を計算するか」。予測には並び順の意味がないので、
「1番目の予測は1番目の正解と比べる」というわけにはいかない。そこで、**損失が最小になるような一対一の対応**を毎回探す:

$$
\hat{\sigma} = \underset{\sigma \in \mathfrak{S}_N}{\arg\min} \sum_{i=1}^{N} \mathcal{L}_{\mathrm{match}}(y_i, \hat{y}_{\sigma(i)})
$$

ここで正解の集合 $y$ は「物体なし」で $N=100$ 個に水増ししたもので、$\sigma$ は100個の予測の並べ替え。
この最適な対応を求めるのが**ハンガリアンマッチング**、対応が決まった後に計算する損失が**ハンガリアン損失**。

### 3.5 ハンガリアンマッチング

**割り当て問題:** コスト行列 $C \in \mathbb{R}^{Q \times M}$（予測 $Q$ 個 × 正解 $M$ 個）が与えられたとき、
各正解に異なる予測を1つずつ割り当て、コストの合計を最小にする問題。
総当たりは $Q!/(Q-M)!$ 通り（$Q=100, M=5$ で約 $9 \times 10^9$ 通り）で現実的でないが、
**ハンガリアン法**（Kuhn–Munkres 法）を使えば多項式時間（$O(n^3)$）で厳密な最適解が求まる。
実装では `scipy.optimize.linear_sum_assignment` を使う（正方でない行列にも対応）。

**DETR のマッチングコスト**（予測 $i$ を正解 $j$ に割り当てるコスト）:

$$
C_{ij} = \lambda_{cls}\cdot\bigl(-\hat{p}_i(c_j)\bigr) + \lambda_{L1}\,\lVert \hat{b}_i - b_j \rVert_1 + \lambda_{giou}\cdot\bigl(-\mathrm{GIoU}(\hat{b}_i, b_j)\bigr)
$$

$\lambda_{cls}=1, \lambda_{L1}=5, \lambda_{giou}=2$。$\hat{p}_i(c_j)$ は予測 $i$ が正解 $j$ のクラスに与えた確率、
ボックスは画像サイズで正規化した $(c_x, c_y, w, h)$。

**GIoU（Generalized IoU）:** 箱 $A, B$ を両方囲む最小の箱を $C$ として
$$\mathrm{GIoU}(A,B) = \mathrm{IoU}(A,B) - \frac{|C| - |A \cup B|}{|C|} \in (-1, 1]$$
IoU は重なっていない箱どうしでは常に 0 で「どれくらい離れているか」の勾配が出ないが、GIoU は離れているほど小さくなるので、
重なっていない予測にも「近づけ」という勾配が出る。また L1 はボックスの大きさで誤差のスケールが変わるが、IoU 系はスケール不変。
両方を組み合わせて使う。

#### ライブラリのコードを読んだ解説（`transformers/loss/loss_for_object_detection.py`）

`DetrForObjectDetection` に `labels` を渡すと、`ForObjectDetectionLoss` が呼ばれ、次の流れで損失が計算される。

**① `HungarianMatcher.forward` — 誰と誰を比べるか決める（勾配は流さない `@torch.no_grad()`）**
1. バッチ全体をまとめて計算するため、予測を `(B*Q, 21)` と `(B*Q, 4)` に平らにし、正解もバッチ全体で連結する（合計 $M_{all}$ 個）。
2. `class_cost = -out_prob[:, target_ids]` … softmax 確率から、各正解のクラスの列だけ取り出してマイナスを付ける → `(B*Q, M_all)`。
   コメントにある通り、損失で使う $-\log p$ ではなく $-p$ で近似している（$1-p$ の定数 1 は割り当てに影響しないので省略）。
3. `bbox_cost = torch.cdist(out_bbox, target_bbox, p=1)` … 全ペアの L1 距離 → `(B*Q, M_all)`。
4. `giou_cost = -generalized_box_iou(...)` … 全ペアの GIoU（cxcywh → xyxy に変換してから） → `(B*Q, M_all)`。
5. 重み付き和でコスト行列を作り、NaN/inf を最大値で置き換え（壊れた予測が選ばれないようにする安全策）、
   `(B, Q, M_all)` に戻して CPU に移す。
6. `cost_matrix.split(sizes, -1)` で正解の列を画像ごとに切り分け、**画像 $i$ の予測 × 画像 $i$ の正解**の部分行列 `c[i]` だけに
   `linear_sum_assignment` をかける。結果は画像ごとの `(予測のインデックス, 正解のインデックス)` のペアのリスト。

**② `ImageLoss.forward` — 対応が決まった後の損失**
1. `num_boxes` = バッチ中の正解ボックスの総数（ボックスの損失はこれで割って平均する）。
2. `loss_labels`: まず全クエリの教師を「物体なし（インデックス 20）」で埋め（`torch.full(..., self.num_classes)`）、
   マッチしたクエリの位置だけ正解クラスで上書きする。そのうえで **全 100 クエリ** に対して重み付きクロスエントロピー。
   重み `empty_weight` は「物体なし」だけ `eos_coef = 0.1`（物体なしが圧倒的に多いので、その影響を 1/10 にしてバランスを取る）。
3. `loss_boxes`: **マッチしたペアだけ** で L1 と $1-\mathrm{GIoU}$ を計算し、`num_boxes` で割る。
   「物体なし」のクエリのボックスには損失をかけない（どこを指していてもよい）。
4. `loss_cardinality`: 「物体なし」以外を出したクエリの数と正解の数の差。**ログ用で、勾配は流さない**。
5. **補助損失:** `auxiliary_loss=True` なら、デコーダの1〜5層目の出力にも同じヘッドをかけて予測を作り、
   **層ごとに改めてマッチングをやり直して**同じ損失をかける（キー名に `_0`〜`_4` が付く）。

**③ 重み付き和** `loss = 1·loss_ce + 5·loss_bbox + 2·loss_giou`（＋各中間層の同じ項）。

### 3.6 従来手法の NMS との違い

**NMS（Non-Maximum Suppression）:** スコア順に予測を見て、すでに採用した予測と IoU が閾値（例 0.5）以上の同じクラスの予測を捨てる。

| | 従来手法（Faster R-CNN, YOLO など） | DETR |
|---|---|---|
| 学習時の割り当て | **多対一**: 正解と IoU が高いアンカー/提案は全部「正例」 | **一対一**: ハンガリアンマッチングで正解1個に予測1個だけ |
| その結果 | 1つの物体に似た予測がたくさん出るように**学習される** | 重複した予測は「物体なし」と教えられるので、重複を出さないように**学習される** |
| 重複の除去 | 推論時に NMS（手作りの後処理、閾値の調整が必要） | 不要（損失の設計に組み込まれている） |
| 重複を避ける情報のやり取り | なし（各アンカーは独立に予測） | デコーダの self-attention でクエリどうしが情報を交換し、担当を分け合える |
| NMS の弱点 | 本当に重なっている2つの物体（人混みなど）を1つに消してしまう、閾値に敏感 | — |

要するに、**NMS が要らないのは「一対一マッチングの損失」と「クエリ間の self-attention」の2つのおかげ**である。
損失が「重複は間違い」と教え、self-attention が「他のクエリが何を取ったか」を知る手段を与える。
どちらかが欠けると重複は消えにくい（元論文では、デコーダの浅い層の出力には NMS が効く＝まだ重複が残っているが、
最終層では NMS を足すとかえってわずかに AP が下がる、と報告されている）。

本実験では `evaluate.py` で (1) NMS を後から足したときの mAP の変化、(2) スコア 0.5 超の予測のうち同じクラスで IoU 0.7 超の
重複ペアの数、を測ってこれを確かめる。

### 3.7 転移学習

**転移学習**は、あるタスク・データ（ソース）で学習した重みを初期値にして、別のタスク・データ（ターゲット）で学習し直すこと。
ターゲットのデータが少ないとき、ゼロから学習するより速く・良い解にたどり着けることが多い。

- **何が転移するか:** CNN の浅い層はエッジや色・テクスチャなど汎用的な特徴、深い層ほどタスク固有の特徴を表す。
  DETR ではさらに「物体クエリの分業」「cross-attention で物体の端を見る」「重複を出さない協調」など、
  **検出というタスクそのもののやり方**が Transformer の重みに入っている。
- **条件 A**（COCO で学習済みの DETR 全体）は、これら全部を引き継ぐ。新しく学ぶのは 21 クラスの分類ヘッド（256×21 の線形層）だけ。
- **条件 B**（ImageNet のバックボーンだけ）は、「画像の特徴の取り出し方」は引き継ぐが、
  Transformer・物体クエリ・ボックスの出し方はゼロから学ぶ。DETR は元論文で COCO に **500 エポック**
  （短い設定でも 150 エポック）かけており、この部分の学習が遅いことが知られている。
- **ファインチューニングの工夫:** バックボーンの学習率を 1/10 にする（事前学習の特徴を壊しすぎない）、
  BatchNorm を固定する（バッチが小さいと統計量が不安定なため）、浅い層（stem と layer1）は凍結する。いずれも元論文と同じ設定。

**DETR が遅く収束する理由**（B が苦戦すると予想する根拠）:
1. 学習初期の cross-attention は画像全体にほぼ一様に広がっており、各クエリが特定の物体に注目できるようになるまで時間がかかる。
2. ハンガリアンマッチングの結果が学習初期は不安定（同じ物体が毎回違うクエリに割り当てられる）で、クエリの役割分担がなかなか固まらない。
3. Transformer には畳み込みのような局所性の帰納バイアスがないので、データから学ぶべきことが多い。

## 4. モデルの構造

`DetrForObjectDetection`（facebook/detr-resnet-50 と同じ構成、パラメータ約 41.5M）。形状は バッチ $B$、入力 $H \times W$ の場合。

```
画像               (B, 3, H, W)       ＋ pixel_mask (B, H, W)（パディング=0）
 │ ResNet-50（BatchNorm 固定、conv1・layer1 は凍結）
特徴マップ          (B, 2048, h, w)    h = ⌈H/32⌉, w = ⌈W/32⌉
 │ 1×1 conv（input_projection）
                    (B, 256, h, w) → 平坦化 → (B, h·w, 256)   ＋ 2次元 sin/cos 位置埋め込み (B, h·w, 256)
 │ Transformer エンコーダ ×6（self-attention 8ヘッド, FFN 2048）
画像のメモリ        (B, h·w, 256)
 │ Transformer デコーダ ×6
 │   入力: ゼロ (B, 100, 256) ＋ 物体クエリ埋め込み (100, 256)
 │   self-attention（クエリ同士） → cross-attention（クエリ → 画像のメモリ） → FFN
クエリの特徴        (B, 100, 256)     （補助損失用に各層の出力 (6, B, 100, 256) も使う）
 ├ 分類ヘッド Linear(256→21)          → logits (B, 100, 21)   … 20クラス＋物体なし
 └ ボックスヘッド MLP(256→256→256→4) → sigmoid → (B, 100, 4)  … 正規化 (cx, cy, w, h)
```

推論時は、各クエリについて「物体なし」を除いた 20 クラスの最大確率をスコアとし、100 個の予測をそのまま出す（**NMS なし**）。

**データの構造とモデルの構造の対応（リポジトリ全体の軸）:**

| データ/出力の構造 | モデルの設計 |
|---|---|
| 出力は個数不定・順序なしの集合 | 固定数（100）のクエリ＋「物体なし」クラス、順序に依存しないハンガリアン損失 |
| 物体どうしは重複してはいけない（一対一） | 一対一マッチング＋クエリ間の self-attention |
| 画像には局所的な構造がある | 特徴抽出は CNN（ResNet-50）に任せる（02 の帰納バイアスを再利用） |
| 物体の判定には画像全体の文脈が必要 | エンコーダの self-attention で全位置の関係を見る |

## 付録A: 発表で聞かれそうな質問と答え

**Q1. なぜクエリは 100 個なのですか？ 物体が 100 個より多かったら？**
A. VOC や COCO の画像1枚あたりの物体数は、最大でも 100 を十分下回るので余裕を持たせた数です。100 個を超える物体は検出できません。
クエリが多すぎると「物体なし」の割合がさらに増え、計算量も増えます。

**Q2. マッチングのコストで $-\log p$ ではなく $-p$ を使うのはなぜですか？**
A. 元論文によれば、$-p$ の方がボックスのコスト（L1 や GIoU、値の範囲が限られる）とスケールがそろい、経験的に性能が良かったためです。
$-\log p$ は確率が小さいと非常に大きくなり、ボックスの近さの情報をかき消してしまいます。

**Q3. 「物体なし」の重みを 0.1 にするのはなぜですか？**
A. 100 個のクエリのうち物体を担当するのは数個だけで、残りはすべて「物体なし」が教師になります。重みを等しくすると、
「全部物体なしと答える」方向に強く引っ張られるので、物体なしの寄与を 1/10 にしてクラスの不均衡を補正します。

**Q4. ハンガリアンマッチングに勾配は流れるのですか？**
A. 流れません。マッチングは「どの予測をどの正解と比べるか」という離散的な選択で、`@torch.no_grad()` の中で計算されます。
勾配は、マッチングで決まったペアについての損失（CE・L1・GIoU）から流れます。

**Q5. 条件 A が良いのは当然では？ この比較に意味はありますか？**
A. 当然の部分が大きいです（VOC のクラスは COCO にすべて含まれる）。この実験の意味は、「同じ構造でも初期値だけでどれほど差が出るか」
「B の Transformer がゼロから学ぶのにどれだけかかるか」を同じ条件で測ることにあり、A の値を一般的な事前学習の効果だとは主張しません。

**Q6. NMS を足すと DETR の mAP は上がりますか？**
A. 十分学習した DETR の最終層では、ほとんど変わらないか、わずかに下がると元論文で報告されています（本当に重なっている物体を消してしまうため）。
本実験でも測定します（6.4 節）。

**Q7. バックボーンの BatchNorm を固定しているのはなぜですか？**
A. 検出は画像が大きくバッチサイズが小さい（ここでは 8）ため、バッチの統計量が不安定になります。ImageNet で学習した統計量と係数を固定して使います。

**Q8. 補助損失（auxiliary loss）とは何ですか？**
A. デコーダの最終層だけでなく、1〜5 層目の出力にも同じヘッドで予測させ、それぞれ損失をかけるものです。
深い Transformer の学習を安定させ、各層が「その時点での最良の予測」を出すように促します。層ごとにマッチングはやり直されます。

**Q9. fp16 で学習しているのに、損失の計算だけ fp32 にしているのはなぜですか？**
A. マッチングのコスト（確率の差や GIoU）は小さな差で割り当てが変わるので、精度の低い fp16 では割り当てが不安定になりうるためです。
重い部分（ResNet と Transformer）だけ fp16 で速くし、ヘッドと損失は fp32 にしています。ライブラリの損失と一致することは確認済みです。

## 付録B: 理解度チェック問題

**問1.** Attention の式 $\mathrm{softmax}(QK^\top/\sqrt{d_k})V$ で、$Q$ が $(100, 32)$、$K$ と $V$ が $(600, 32)$ のとき、
attention の重み行列と出力の形はそれぞれ何か。

<details><summary>答え</summary>

重み行列は $QK^\top$ の形なので $(100, 600)$（各行が 600 個の Key への確率分布）。出力は重み行列 × $V$ なので $(100, 32)$。
DETR のデコーダの cross-attention で、クエリ 100 個が $h \cdot w = 600$ 個の画像特徴を見る場合（1ヘッドあたり 32 次元）に相当する。
</details>

**問2.** 正解が 3 個、クエリが 100 個のとき、分類の損失の教師のうち「物体なし」は何個か。ボックスの損失は何個の予測にかかるか。

<details><summary>答え</summary>

物体なしは 97 個（マッチしなかったクエリ全部）。ボックスの損失はマッチした 3 個の予測にだけかかる。
</details>

**問3.** 同じ犬に対して、ほぼ同じボックス・同じクラスを出している予測が2つある。DETR の損失はこの2つをどう扱うか。
従来の多対一の割り当てとの違いは？

<details><summary>答え</summary>

一対一マッチングなので、コストの小さい方だけが犬に割り当てられ、もう片方の教師は「物体なし」になる。
よって重複した方は「犬」の確率を下げるように学習される。従来の多対一の割り当てでは、犬と IoU が高い予測はどちらも「犬」として正例になるので、
重複が残ったまま学習され、推論時の NMS で消す必要がある。
</details>

**問4.** ハンガリアンマッチングのコストに GIoU だけでなく L1 も入れるのはなぜか。逆に L1 だけではだめなのはなぜか。

<details><summary>答え</summary>

L1 は座標の誤差を直接測るが、箱の大きさによって同じ L1 誤差でも重なり具合の意味が変わる（小さい箱には厳しく、大きい箱には甘い）。
GIoU はスケール不変で重なり具合を測れるが、それだけだと座標そのものの細かい合わせ込みの信号が弱い。両方を組み合わせると補い合える。
GIoU は IoU と違い、重なっていない箱にも距離に応じた値を返すので、学習初期の離れた予測にも勾配が出る。
</details>

**問5.** 条件 A で新しく初期化されるパラメータはどこか。また、その数はおよそいくつか。

<details><summary>答え</summary>

分類ヘッド `class_labels_classifier`（Linear 256→21）だけ。重み $256 \times 21 = 5{,}376$ ＋ バイアス 21 = 5,397 個。
モデル全体（約 4,150 万）のうちごく一部で、ボックスヘッドや Transformer・物体クエリはすべて COCO の学習済みの値を使う。
</details>

**問6.** 「A の mAP が B よりはるかに高かったので、事前学習は物体検出にとって非常に重要だ」と結論してよいか。

<details><summary>答え</summary>

そのまま一般化してはいけない。VOC の 20 クラスはすべて COCO に含まれ、画像の傾向も近いので、A はターゲットのクラスをすでに学習済みの状態から始まっている。
言えるのは「ソースとターゲットが非常に近い場合に、同じエポック数でこれだけ差が出た」ということまで。
また 5 エポックでの比較なので、B が長く学習すれば差が縮まるかどうかもこの実験からはわからない。
</details>

**問7.** DETR のエンコーダの self-attention で、位置埋め込みを Q と K には足すが V には足さないのはなぜだと考えられるか。

<details><summary>答え</summary>

Q と K は「どこを見るか（注目の重み）」を決める部分なので、位置の情報があれば「近くを見る」「同じ行を見る」などの位置に基づく注目ができる。
V は実際に運ばれる中身なので、画像の内容の特徴だけを運び、位置の情報で中身を汚さない設計になっている。
（元論文の実装の選択であり、他の入れ方でも動くが、この入れ方が経験的に良かったとされている。）
</details>
